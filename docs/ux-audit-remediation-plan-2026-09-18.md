Подтверждён переход из главной в общий список задач: на следующий день отображаются три задачи тестового workspace.
- Уточнена область виджета на главной: он показывает именно «Мои задачи», а менеджеру даёт явный переход «Все задачи» к командному списку. Фильтр типов задач получил доступное имя и состояние раскрытия; в локальном браузере проверено отображение раскрытого фильтра с двумя вариантами. Причина расхождения счётчиков — виджет отбирает задачи, назначенные текущему сотруднику, тогда как общий список включает задачи команды.

- Целевые тесты компоновки, карточки задачи и создания смены, проверка TypeScript и production-сборка `web-admin` прошли. Локальный контейнер пересобран и запущен; это не подтверждает прод и не закрывает весь пакет TASK-03 / ACT-01 / HOME / CAL.

## Цель

Владелец должен самостоятельно настроить компанию, пригласить сотрудника, назначить смену и задачу, увидеть результат и разобраться в отклонениях. Сотрудник должен принять приглашение, завершить регистрацию, отметить приход/уход и сдать задачу с фотографией без технических тупиков.

Приоритеты:

- **P0:** невозможно завершить ключевой сценарий.
- **P1:** сценарий затруднён, действие недоступно или его результат непонятен.
- **P2:** навигация, согласованность интерфейса и скорость ежедневной работы.
- **P3:** дополнительные улучшения и развитие механик.

## Как вести выполнение

Записи ниже — хронология пакетов. Их промежуточные ограничения могут быть сняты более поздним пакетом; актуальный статус каждого ID приведён в реестре в начале документа.

### Продолжение: личная история посещаемости (MOB-04, готово к проверке)

- Раздел «Сегодня» в режиме учёта посещаемости показывает явный переход к истории приходов и уходов. В режиме «только задачи» переход скрыт вместе с блоком посещаемости.
- Новый мобильный экран читает существующий защищённый API `/attendance/me/history` и показывает отметки за выбранный месяц, локацию, статус смены, время прихода и ухода. Доступны предыдущие месяцы, обновление, пустое состояние и повтор после ошибки.
- Сквозная приёмка на Android/iOS остаётся открытой: сотрудник с историей и без неё, разные локации, смена через полночь, отсутствие сети и смена workspace.

### Продолжение: запрос корректировки времени (MOB-05, локально; требуется приёмка)

- Из личной истории сотрудник может запросить исправление времени прихода или ухода для конкретной смены, указав причину. Запрос уходит в существующий процесс согласования, повторный запрос при ожидающем решении скрыт.
- В истории отображаются причина, статус и комментарий по решению каждого запроса. API отдаёт сотруднику только запросы по его сменам и запрещает создавать запрос на чужую смену; права менеджеров сохранены.
- Согласующий видит ожидающие заявки в web-разделе посещаемости, исходное и предлагаемое время, причину, может одобрить либо отклонить с обязательным в интерфейсе пояснением. Сервер проверяет назначенного согласующего и фиксирует решение в аудите.
- Требуется сквозная приёмка на Android/iOS: ночная смена, открытая смена без ухода, отсутствие согласующего, отклонение/одобрение и обновление истории после решения.
- Docker-сборки API и web-admin прошли, оба локальных контейнера перезапущены и работают; API отвечает на healthcheck. Ничего из этого пакета ещё не опубликовано на проде.

### Продолжение: причины неуспешной отметки (MOB-06, локально; требуется приёмка)

- Мобильный экран ждёт подтверждения отметки от API до перехода на «Сегодня». Ошибка больше не скрывается за оптимистическим состоянием; после подтверждения устаревший кэш сбрасывается.
- API передаёт стабильные коды для выхода из геозоны, недостаточной точности и неуспешной/устаревшей проверки лица. Мобильный экран показывает причину и действие: повторить локацию, открыть настройки разрешений или переснять лицо.
- Неоднозначный сетевой сбой при отправке отметки не запускает автоматический повтор POST. Сначала предлагается проверить фактический статус смены; повторное сканирование доступно, только если отметка не появилась.
- Нужна приёмка на реальном устройстве: отказ в геолокации/камере, плохая точность, выход из зоны, ошибка лица, потеря сети до и после принятия POST и отсутствие дублей.

### Продолжение: ручной ввод времени (MOB-07, локально; требуется приёмка)

- Общий мобильный пикер для смен, времени перерыва и переноса задач получил поля часов и минут рядом с колесом. Ручной ввод синхронизируется с колесом; пустые значения и выход за допустимые часы/минуты блокируют применение.
- Для локалей с 12-часовым временем ввод показывает AM/PM и преобразует полдень/полночь в корректное внутреннее 24-часовое значение. Длительность перерыва не трактуется как время суток и остаётся в 24-часовом формате.
- Локальные проверки типов и тесты границ времени прошли. Нужна визуальная приёмка на Android/iOS: RU/EN и другие локали, клавиатура, прокрутка колеса, AM/PM, полночь, полдень и длительность перерыва.

### Продолжение: управление видимостью и прогресс рейтинга (RATE-03/04, локально; требуется приёмка)

- Настройка видимости оформлена как доступный переключатель. Подпись объясняет фактическую область действия: вся компания, все локации и месяцы; сотрудники видят своё место и очки, руководители — полный рейтинг. Состояние меняется только после подтверждения сервера, показаны сохранение и результат.
